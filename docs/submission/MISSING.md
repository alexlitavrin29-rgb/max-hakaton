# Что дополнить перед отправкой

## Данные от команды

- Название и ID команды, состав, роли, контакт для жюри. `teamId` необязателен
  по схеме, поэтому он пока не указан, а не заменён выдуманным значением.
- Отдельный аккаунт MAX для проверки и согласованный защищённый способ передачи
  доступа либо свежего Bearer-сеанса. Пароли и токен бота в архив не добавлять.

## Проверки перед окончательной сдачей

- Доступность публичного HTTPS из сети организаторов. Независимые узлы в России,
  США и Гонконге получили HTTP 200; рабочий Windows не устанавливает TCP/443.
  Владелец подтвердил работу приложения на телефоне.
- Для защиты полезно приложить короткую запись конкретных действий с двумя
  тестовыми аккаунтами, если её разрешено передать жюри.
- Ограниченный запрос HH из локального проверочного контейнера выпуска r5
  вернул HTTP 403, но активный miniapp-контейнер VPS до и после установки r5
  получил HTTP 200 и одну вакансию. Причина расхождения между окружениями
  не установлена; перед демонстрацией проверьте живой поиск.
- Назначить публичный контакт для запросов о данных. Кнопка удаления очищает
  рабочую БД; прежние резервы удаляются по установленному сроку 30 суток.
- Выбрать отдельное от VPS место для зашифрованной копии и проверить
  восстановление из него. Текущие ежедневные резервы остаются на самом VPS.
- Решить, нужна ли в будущем сортировка помощи по расстоянию. Новый комплект
  совпадает с опубликованным порядком и текстами VPS.

## Что усилит продуктовую защиту

Нужны результаты пилота/интервью, если они есть: аудитория, число участников,
методика, реальные результаты и разрешённые к показу обезличенные отзывы.
Пока нет оснований заявлять доказанный социальный эффект, покрытие всей страны
или SLA 99%. Для бонуса +0,15 полезны короткая запись экрана телефона и
демонстрация MAX-функций. Бонус присуждает жюри.

Презентация оставляет эти ограничения явными. После получения сведений команды
обновите первый слайд и пересоберите архив, чтобы хеши соответствовали файлам.
