удалила только свой Compose-проект. Сценарий в комплекте: публикация **9**,

отправлял. Владелец ранее проверил приложение на настоящих аккаунтах MAX.

Результаты таблицы относятся к полному выпуску r5 в GitVerse. В GitHub
публикуется тот же код без исходного журнала `work.jsonl` (156 МБ):
пять replay-тестов читают те же раскрытые случаи из уже включённого
`repair-packet-private.json`. Для GitHub-дерева отдельно проверены все пять
replay-тестов и манифест 267 файлов; полный набор на этой копии пока не запускался.

Повторный выпуск также клонирует Git bundle в пустой каталог, сверяет commit,
манифест и чистоту рабочего дерева. Нагрузочные результаты предыдущей
технической редакции отдельно приведены в [LOAD.md](LOAD.md); их нельзя
выдавать за 40-минутный прогон нынешнего r5.

Первый тест идемпотентности на исходном r5 воспроизвёл дефект: одинаковый ключ
с другим телом давал HTTP 200 и выполнял второе действие. Исправлен индекс
результата в PostgreSQL: ключ привязан к хешу тела. Кэш ограничен пятью минутами.
При миграции существующей БД старые пятиминутные записи этого кэша очищаются,
поскольку по прежнему хешу нельзя восстановить исходный ключ; состояние сеансов
и сохранения не удаляются. Новый код проверен на чистой и уже созданной БД.

Тесты HH воспроизвели попытку перевыпуска токена после 403 и передачу токена
в `/areas`. В выпуске запрос `/areas` идёт без bearer, а 403 не вызывает
`/token`. При искусственном 403 поиск сохраняет вакансии «Работы России» и
показывает понятное сообщение о частичной выдаче без кода и текста провайдера.
Один ограниченный живой запрос к `/vacancies` из локального проверочного
контейнера вернул **403**; запрос с рабочего Windows не установил соединение.
Активный miniapp-контейнер VPS до и после установки r5 вернул **200 и одну
вакансию**. Причина расхождения окружений не установлена. Рабочая интеграция
HH доступна в проверенном серверном запросе; дальнейшая выдача зависит от HH.

Для ProxyAPI тесты проверили обычный ответ, JSON-ответ и ошибки. Ключ и текст
пользователя не попали в диагностический лог; поле `failed_generation`, которое
могло содержать их, удалено из метрик. Живой ответ ProxyAPI этим прогоном не
проверялся при сборке ZIP. После установки на VPS активный ProxyAPI с рабочими
параметрами вернул непустой обычный ответ и корректный JSON-объект на два
коротких синтетических запроса. Дальнейшие ответы зависят от внешнего сервиса.

## Установка на VPS

Перед переносом сохранены дамп PostgreSQL, конфигурация и исходники в
`/opt/tochka/backups/r5-before-20260928T125332Z`; SHA-256 и список
`pg_restore` проверены. Перенесены только `project/miniapp/app.py`,
`project/miniapp/session_store.py` и `project/llm/services/llm.py`.
Пересобраны и запущены admin, miniapp, bot; хеши файлов в активных контейнерах
совпали с выпуском. Bot и miniapp healthy, внешний HTTPS `/api/health` с VPS
вернул 200. В БД остались публикация 9, черновик 56 и `child_only=true`.
Подписанный синтетический сеанс проверил прежний ответ при повторе, HTTP 409
при том же ключе с другим телом, следующий шаг с новым ключом и HTTP 401 после
удаления аккаунта. Сообщения MAX не отправлялись.

## Срок хранения резервных копий

На VPS установлен срок **30 суток** для ежедневных и ручных архивов с дампами
в `/opt/tochka/backups`. Очистка запускается systemd после успешного создания
ежедневной копии. Тесты проверили границу срока, исключение посторонних файлов,
символических ссылок и непомеченных каталогов. Режим без удаления на VPS дал
`expired=0 removed=0`. После подключения правила служба успешно создала
проверенную копию `20260928T131256Z`; очистка снова дала
`expired=0 removed=0`. Уже созданные копии аккаунта остаются до истечения
этого срока либо досрочного удаления администратором.
Действующий скрипт создания копий перенесён в `project/deploy/backup_managed.sh`
без изменения содержимого. VPS теперь запускает его из этого пути; полный
цикл повторён с копией `20260928T135714Z`, результат службы `success` и
`expired=0 removed=0`.

Новый ZIP, чистое Git-дерево, bundle и receipt с SHA-256 лежат рядом в `dist/`.
Старые логи с прежними падениями и исторические сравнительные отчёты не входят
в ZIP; исходная рабочая история не удалялась. Скрипты и действующие тесты входят
в комплект. Доступ из сети жюри, действующие объявления и условия HH остаются
внешними или организационными вопросами; оценка 90+ не гарантируется.
