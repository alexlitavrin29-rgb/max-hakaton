# COV — облачная доработка жизненных ситуаций

Пакет заданий от 21.10.2026. **COV** обозначает расширение покрытия жизненных ситуаций в планировщике, справочнике и чате «Точки опоры». Это отдельная программа с заданиями **COV-02…COV-06**. Исторические этапы K0…K5 не продолжать и не переименовывать.

Сейчас **COV-01 завершён и установлен**: release `f702edc4435383f8d70d2cf1bea1d1065d423f83`, отчётный коммит `5a0abdaf56a92a4ec6fc5cf212d0a1453a851685`. Проверены 1298 Python-тестов, Node, Chromium и установленный HTTPS/API-путь. [Краткая передача COV-01](COV-BASELINE.md). Задания COV-02…COV-06 ещё не выполнялись.

## Где открыть в облаке

Пакет находится в **main** двух репозиториев: `alexlitavrin29-rgb/max-hakaton` (MAX-хакатон) и `alexlitavrin29-rgb/tochka-opory-codex`. В облаке выбери нужный репозиторий и **main**. В корне каждого есть COV-CLOUD.md и ссылка в README.

Это публикация заданий. Она не переносит реализацию планировщика из отдельной рабочей ветки. Перед COV-02 прочитай [COV-BASELINE.md](COV-BASELINE.md) и проверь исходный код: если нужных модулей нет, сначала требуется согласованный перенос базы.

Рабочий каталог — фактический checkout облачной задачи. Локальная Windows-папка, SSH-ключи владельца и локальные MCP-подключения для реализации не нужны и в пакет не входят. Код, исследования, тесты, отчёты и независимый review выполняются в облаке. Результат передаётся через GitHub/коммиты согласованного процесса задачи; от владельца не требуется вручную переносить исправления в исходники.

Сам этот пакет не запускает задачи или реализацию автоматически. Владелец выдаёт задания последовательно и отдельно назначает независимого проверяющего. Реальная установка требует разрешённого серверного доступа у интегратора; если его нет в облачной среде, передаётся точный handoff, а установка не объявляется выполненной. Публикация кода/PR и публикация на рабочем сервере остаются разными проверяемыми результатами.

## Цикл каждого задания

| Метка | Результат | Ответственный |
|---|---|---|
| COV-A | Проверенные источники, материалы, контракт, кейсы | Исполнитель |
| COV-B | Объяснимое воспроизведение дефектов до исправления | Исполнитель |
| COV-C | Реализация, проверки, фактические ответы, коммит | Исполнитель |
| COV-D | Независимый review этого коммита | Проверяющий |
| COV-E | GitHub, рабочая установка и проверка после неё | Интегратор |

В существующем JSON ключи `gates.K1…K5` оставлены совместимыми и имеют отображение COV-A…COV-E. Это контрольные точки внутри задания COV, а не задачи старого цикла K. Однозначные поля: `program_id=COV`, `id=COV-NN`, `stage=N`. Отчётные каталоги `stage-02`…`stage-06` сохраняются, чтобы история не разделилась на два реестра.

Исполнитель завершает COV-A–COV-C (60%), затем передаёт результат на [COV-REVIEW](COV-REVIEW.md). Замечания исправляются по [COV-FIX](COV-FIX.md), одобренный результат выпускается по [COV-RELEASE](COV-RELEASE.md). Независимый review — 80%, проверенная интеграция — 100%. Следующий этап начинается после COV-E.

## Текст для первой облачной задачи

Название: **COV-02 — бюджет, мошенничество и поиск помощи**.

```text
Работай в облачном checkout репозитория, выбранного владельцем:
max-hakaton или tochka-opory-codex (владелец alexlitavrin29-rgb).
Исходная ветка пакета: main. Не переключай репозиторий автоматически.
Задание: COV-02 программы «Покрытие жизненных ситуаций».
Прочитай docs/superpowers/plans/planner-coverage-agents/COV-CLOUD.md,
00-common.md, 10-handoff.md и COV-02-money-fraud-help.md из той же папки.
Прочитай COV-BASELINE.md. Проверь PROGRESS.json и актуальную кодовую базу.
Если модулей планировщика нет, подготовь handoff на согласованный перенос,
не импортируя закрытую историю самостоятельно.
Выполни только COV-02 до COV-C, с исследованиями, red/green,
необходимыми PostgreSQL/Node/браузерными проверками и фактическими ответами.
Подготовь коммит и HANDOFF для независимого COV-REVIEW.
Не начинай COV-03, не публикуй на VPS и не создавай других агентов.
При отсутствии платного бюджета закончи автономные проверки и укажи пределы.
```

Для следующих заданий меняются только ID, название и файл исполнителя после проверки зависимости. Для проверки и выпуска владелец передаёт соответствующий общий промпт отдельной задаче.
