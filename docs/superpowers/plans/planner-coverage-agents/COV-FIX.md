# COV-FIX — исправления по независимой проверке

Работай только с программой `COV`: проверь `program_id`, `id` задания и `active_stage` в PROGRESS.json. Используй фактический checkout облачного репозитория. Контрольные точки COV-A–COV-E сопоставляются с прежними ключами JSON по `00-common.md`.

Исправь замечания независимого review текущего этапа «Точки опоры». Прочитай применимые AGENTS.md, если они есть в checkout, `00-common.md`, `10-handoff.md`, ТЗ, PROGRESS.json, промпт этапа, HANDOFF.json и REVIEW.md. `active_stage` должен однозначно указывать на этап со статусом `needs_changes`.

1. Проверь фактический HEAD и чужие изменения. Сопоставь каждый пункт review с кодом, источниками и воспроизведением. Если замечание основано на неверном предположении, объясни это проверяемыми данными в ответе к замечанию; не вноси ошибочную правку ради согласия.
2. Составь короткий список «ID замечания → тест → минимальное исправление → проверка». Не расширяй объём следующими этапами и необязательным рефакторингом.
3. Для дефекта поведения сначала добавь/уточни значимый тест и покажи нужное падение, затем исправь. Для ошибки источника перепроверь первичную страницу, исправь карточку и проверку её доступности/условий; не сочиняй искусственный красный тест для чистой опечатки.
4. При изменении контракта согласованно обнови API, UI/чат, черновик, каталог и тесты затронутого пути. Перепроверь требования выбранного приоритета и срочной помощи.
5. Обнови источники, CONTRACT/MATERIALS/CASES и фактические RESULTS там, где поведение изменилось. Прошлый вывод не выдавай за результат новой версии.
6. Выполни целевые и необходимые регрессионные проверки. Сохрани в TESTS.md реальные команды, red/green и ограничения. Платные вызовы — только в рамках актуального бюджета.
7. Зафиксируй изменения отдельным коммитом реализации; обнови `implementation_sha`. Любое изменение продукта сбрасывает `reviewed_sha`, `release_sha`, COV-D/COV-E. COV-A–COV-C сохраняй только после повторной проверки затронутых доказательств; незавершённую точку оставь открытой.
8. Запиши по каждому замечанию результат: исправлено с доказательством, обоснованно оспорено или не закрыто. Не удаляй старый review; новый запуск проверяющего должен видеть историю.

Если обязательные исправления завершены, статус `ready_for_review`, максимум 60%, передача на `COV-REVIEW.md`. При незакрытых дефектах оставь `needs_changes` и назови препятствие. Сам себе COV-D не выставляй, на сервер не публикуй.
