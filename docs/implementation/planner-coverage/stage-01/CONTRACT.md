# Этап 1: контракт, 21.10.2026

Происхождение: принятый COV-01, reviewed d20fe3c, release f702edc. Это контракт интерфейса, не наличие кода в текущей main.

## Запрос и ответ

Сохраняются `PlannerAI.propose(owner, operation, text, question_id=None, answer=None, *, config=None)` и шесть ID категорий: documents, housing, benefits, work, help, study. Добавляется необязательный keyword `description=None` и поле API `description`: непустая строка до 500 символов, дополнение к исходному `text`, не замена ему. `text` остаётся до 160 символов. Поля question_id/answer всегда парные; topic_choice принимает только шесть ID. Новый QUESTIONS ID `situation_description` принимает свободный answer (1–500 символов после trim). Произвольные ID запрещены.

Запрос с situation_description сначала проверяется на непосредственную опасность; иначе всегда возвращает clarify/topic_choice с допустимыми choices, без tasks, goal_id, context/policy. В UI description хранится отдельно; при выборе категории передаётся `description`, question_id=topic_choice, answer=ID. Сервер использует совокупный контекст для смысла и безопасности, но title и context.question сохраняют исходный text. Модель не может завершить situation_description готовым планом.

## Переходы UI

question → clarify/topic_choice. «Пока не знаю» → конкретные жизненные ситуации; повторное «Не знаю» либо «Описать своими словами» → clarify/situation_description. «Всё важно» открывает ситуации с подсказкой выбрать срочную потребность. «Вернуться к выбору темы» возвращает topic_choice без потери исходного текста и описания. После описания требуется явный выбор. «Сменить тему» из справки/предложения сбрасывает information/proposal/selection/pendingMaterials и clarifyingProposal. Следующее действие — получение справки, затем отдельное предложение плана. Быстрые повторные нажатия блокируются waiting. Ошибка сохраняет введённое. Лимит не обрезает текст.

Черновик: дополнительные поля description и showGuidance сохраняются существующим JSON codec, без миграции БД. Старый showGuidance=true открывает список ситуаций; старые proposal не возобновляются после смены темы. Поле свободного ответа восстанавливается по questionID. Справочник открывается отдельной кнопкой при сбое модели.

## Ситуация → категория → материал → действие

| Ситуация | Категория | Материалы | Действие |
|---|---|---|---|
| Нет денег на необходимое | help | существующий доступный каталог | уточнить потребность; бюджет не подменяется выплатами |
| Работа/доход | work | существующий каталог | действующее уточнение/справка |
| Жильё | housing | существующий каталог | действующее уточнение/справка |
| Документы | documents | существующий каталог | действующее уточнение/справка |
| Учёба | study | существующий каталог | действующее уточнение/справка |
| Тяжело, нужна поддержка | help, с description | support_services, support_mchs_online, support_mchs_phone, support_child_line | выбрать способ связи; открыть страницу/набор номера только по нажатию |
| Явная текущая личная опасность | без выбора категории | personal_safety | information.priority=urgent, tasks=[], без модели и плана |

Психологические карточки добавляются через существующий adjacent_guides, привязаны к доступному детской роли bq_legal_help. Отсутствие/закрытие/непроверенный статус anchor либо явная скрытая карточка исключают маршрут. Содержание новых карточек source_checked_reference; старые статусы не повышаются. Контакты доступны в handbook независимо от провайдера. PLANNER_AI_ENABLED/LLM_ENABLED и авторизация сохраняются. Нет внешних запросов к службам во время диалога.

Поддержка — детерминированная справка из каталога. До выбора при неоднозначности план запрещён. При явном единственном запросе поддержки доступна справка без категории; предложение по отдельному draft_plan использует только подготовленные действия обращения. При отсутствии проверенного support_services — information с текстом «Пока у нас недостаточно проверенных материалов по этой ситуации», tasks=[] и без обращения к провайдеру. Технический отказ остальных запросов остаётся unsupported/unavailable. Пробел не превращается в шаблон плана.

Общее правило пробела: если нет ни материала, ни подходящего существующего поискового ресурса, enrich возвращает information/tasks=[] без context/policy и без трёх шаблонных дел. Действующий явно запрошенный поиск остаётся доступен. Это намеренно заменяет прежнее обещание составить общий план при отсутствии знаний (R08).

## Предварительная проверка интерфейсов и решения

Задача 1 → 2 → 3: description должен одновременно сохраняться в запросе API, UI, черновике и эффективном контексте PlannerAI; иначе выбор после описания потеряет смысл. Проверки охватывают все четыре границы.

Ruling: использовать существующую категорию help для поддержки — сохраняет валидацию шести категорий; цена ошибки: понадобится отдельный ID категории в следующем согласованном изменении.

Ruling: необязательные НКО/университетские карточки отложены при неполных/противоречивых условиях; обязательный государственный пакет остаётся. Цена: меньше вариантов в первом выпуске.

Ruling: независимый review выполняет назначенный владельцем проверяющий после K3; исполнитель не запускает review-агента. Цена: K4 остаётся открытым до отдельной проверки.

## Уточнение после review S1-R1–R3

Подготовленная поддержка не назначает приоритет вместо пользователя: при одновременном запросе работы, жилья, документов, учёбы или выплат сначала возвращается topic_choice. Обе операции запрещают tasks/context/policy/goal_id до выбора; API не резервирует предложение. Явный выбор help допускает только действия поддержки.

Упоминание профессии психолога и явный отказ от консультации остаются в обычном классификаторе темы. Это не доказательство качества живой модели: её контракт отдельно проверяется сохранённым ответом.

«Не могу причинить себе вред» и «умереть от смеха» не являются достаточными признаками текущей опасности. При явной опасности в следующей самостоятельной части запроса срочный маршрут сохраняется. Справочные факты, API/черновик/UI-контракт и карточки не менялись.
