# Развёртывание на VPS

`compose.yml` описывает рабочие PostgreSQL, admin, miniapp, bot и Caddy.
`Caddyfile` содержит публичные маршруты. Значения `.env` и
`.deploy-secrets.env` хранятся только на сервере и в Git не входят.
`submission/compose.yaml` служит для воспроизводимого запуска на чистой БД;
его не следует использовать вместо рабочего Compose с текущими данными.

Ежедневный `tochka-backup.timer` запускает `tochka-backup.service`.
На действующем VPS drop-in `tochka-backup-managed.conf` направляет службу на
`backup_managed.sh`: после дампа и архива конфигурации проверяются SHA-256 и
список `pg_restore`. Drop-in `tochka-backup-retention.conf` запускает
`prune_backups.py --apply` только после успешного создания копии. Срок —
30 суток; без `--apply` скрипт лишь считает просроченные копии. Копии остаются
на самом VPS, поэтому для защиты от полной потери сервера требуется отдельное
место хранения и проверка восстановления из него.

Изменения публикации сценария MAX не входят в установку кода: действующая
публикация 9 и `rules.child_only=true` сохраняются.
